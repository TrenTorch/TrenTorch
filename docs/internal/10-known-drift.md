# 10. Known Drift, Gaps and Risks

Found while reading every file. Ordered roughly by impact.

## Behavior gaps

1. RPC `record_potd_attempt` is called by `processes/progress-tracking/supabase-potd-attempts-store.ts` but no migration in this repo defines it. Either it exists in Supabase from an earlier manual change, or the call silently fails (errors are swallowed). Confirm in the database; if it is missing, POTD attempt history is not being written. The other `recordPotdAttempt` in `supabase-rating-store.ts` writes `potd_attempts` directly, so two paths write the same concept.
2. `potd_schedule` seed has one row (ridge regression, 2026-09-14, hard) while `data/potd.ts` has 39. `record_potd_outcome` validates against the table, so outcomes for unseeded dates may be rejected. The table must be kept in sync by hand.
3. Migrations cannot rebuild the schema: `profiles` and `solved_questions` are created outside the repo.
4. The curriculum JSON is not regenerated by `npm run build`. Forgetting the compile step ships stale content.
5. Fixed: `data/part-icons.ts` now has icons for part-python, part-numpy and the three newest Parts (they used the fallback icon).
6. Fixed: `supabase-solved-store.ts` calls now use a 15 s abort signal like every other remote call.
7. Difficulty vocabularies differ across layers: display Easy, Medium, Hard; generated content Beginner, Intermediate, Advanced, Mastery; rating easy, medium, hard, advanced (mapped by `RATING_DIFFICULTY_MAP`).
8. CI uses Node 22 while `.nvmrc` and `engine-strict` say 24.19.0.
9. `RatingBadge` colors are documented as placeholders pending a design task.
10. `platform/lib/vitest-examples/greet.ts` is template residue.
11. Pre-existing on a local run: 5 unit tests fail (3 in `gate-behind-sign-in.spec.ts`, 1 in `preview-mode.spec.ts`, 1 in `extract-simple-version.spec.ts`), identical with and without the changes on branch docs/internal-documentation. The preview-mode test expects `VITE_PREVIEW_SKIP_SIGN_IN` to be unset, so check whether it is set in the local environment first.

## Risks worth watching

- Sync is last write wins by timestamp for drafts and union for progress: a solved slug removed on one device can come back from another device that still has it locally.
- KV is eventually consistent, which is why the client polls after connecting GitHub; any new feature reading KV right after a write needs the same care.
- A single shared `TOKEN_SECRET` derives both the HMAC and AES keys (with different derivations). Rotation logs out every GitHub connection.
- Pyodide 0.27.2 is pinned in three places (worker import URL, service worker cache name, `vitest.pyodide.config`). Upgrade all together.
- The test harness supports only `pytest.raises` and `tmp_path`; content authors can write tests that pass under CPython and fail in the browser. The Pyodide check suite is the guard.
- Lazy failure settlement for POTD depends on the user opening the site; there is no cron.
