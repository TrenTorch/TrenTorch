# Questions Page: Implementation Plan

Spec: `docs/specs/2026-09-08-questions-page-design.md`

## Goal

Add a `/questions` page (profile + progress on the left, curriculum questions grouped by Part on the right, each linking to `/questions/[slug]`) and a "Questions" button on the homepage, using `shadcn-svelte` + `bits-ui` components.

## Architecture

- Static data (`src/lib/data/questions.ts`) seeded from the curriculum designed in this project's planning session (Part 0 to Part 4), no backend yet.
- Five small presentational Svelte components, each independently reusable.
- One route (`src/routes/questions/+page.svelte`) that composes them.
- `shadcn-svelte`'s CLI copies component source into `src/lib/components/ui/`; `bits-ui` is the one new runtime dependency those copied components need.

## Tech stack

SvelteKit 2 / Svelte 5 (existing), Tailwind v4 (existing), `shadcn-svelte` (new, dev-time CLI), `bits-ui` (new, runtime).

## Files to create

- `src/lib/data/questions.ts`: types, data, `getProgressStats()`
- `src/lib/data/questions.spec.ts`: data-integrity tests
- `src/lib/components/DifficultyBadge.svelte`
- `src/lib/components/ProfileCard.svelte`
- `src/lib/components/ProgressSummary.svelte`
- `src/lib/components/QuestionRow.svelte`
- `src/lib/components/ModuleSection.svelte`
- `src/routes/questions/+page.svelte`
- `src/lib/components/ui/progress/*`, `ui/avatar/*`, `ui/accordion/*`, `ui/badge/*` (generated by `shadcn-svelte add`, not hand-written)
- `components.json` (generated by `shadcn-svelte init`)

## Files to modify

- `src/routes/+page.svelte`: add a "Questions" button to the hero CTA row
- `package.json`: adds `bits-ui` dependency, `shadcn-svelte` devDependency (both via the CLI, not hand-edited)

## Files to test

- Manual: `npm run dev`, visit `/`, click Questions, visit `/questions`, expand/collapse a Part, confirm each question row is a real link

function slugify(title: string): string {
	return title

## Execution choice

This is 11 small, mostly-independent tasks (data seeding, one component per task, one route, one homepage edit) with a couple of real ordering dependencies (data before components that import its types, components before the route that composes them). Recommend **inline execution with a checkpoint every 3 tasks**, this is small enough end-to-end that spinning up fresh subagents per task would cost more in re-established context than it saves.
