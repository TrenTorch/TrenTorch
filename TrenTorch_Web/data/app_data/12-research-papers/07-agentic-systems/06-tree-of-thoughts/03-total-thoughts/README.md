## Statement

### The problem, from first principles

The cost of a tree search grows fast: each step multiplies the number of thoughts by the branching factor. Counting the thoughts makes that cost explicit, which is why the beam and pruning exist.

### From theory to code

Implement `total_thoughts(b, depth)`, the total number of thoughts generated by a full breadth search.

### Constraints

- Return an integer.

### Hints

<details>
<summary>Hint 1</summary>

Sum the powers of the branching factor from one to the depth.

</details>

## Theory

### The simple version

With branching b, depth d costs about b to the d, so small reductions in branching or depth save a great deal of model calls.

### The formula

$$N = \sum_{t=1}^{d} b^{t}$$

### How NumPy/PyTorch actually implements this

Budget planners for tree-search agents compute this count to estimate the number of model calls per task.

## Explanation

The geometric sum is what makes the total grow roughly as the last level, b to the d.
