## Statement

### The problem, from first principles

A large network with millions of parameters can, during training, start relying heavily on a small number of specific neurons acting in a very particular coordinated way, a kind of overfitting where different neurons become "co-adapted" to compensate for each other's specific quirks rather than each independently learning something generally useful. Dropout is a strikingly simple fix: on every training step, randomly zero out a fraction of the neurons' activations entirely, forcing every OTHER neuron to be independently useful, since it can no longer count on any particular teammate being present on the next step. At test time, all neurons participate (no zeroing), so the network gets to use its FULL capacity when it actually matters.

There's a subtlety in exactly how the surviving activations get treated, and it's the crux of this question: if training randomly zeroes out a fraction `p` of activations but test time uses ALL of them, the total activation magnitude flowing into the next layer would systematically differ between training and testing, which would itself hurt the network's performance. "Inverted dropout" fixes this by rescaling the SURVIVING activations during training (by `1 / (1 - p)`) so their expected magnitude matches what test time will see, meaning test time needs NO special-casing at all.

### From theory to code

Implement `dropout_forward(x, mask, p)` and `dropout_backward(grad_output, mask, p)`. `mask` is a same-shape 0/1 array already generated by the caller (1 = keep this entry, 0 = zero it out); you are not responsible for generating the random mask itself, only for correctly applying it with the inverted-dropout rescaling.

### Constraints

- Every entry where `mask == 0` must be exactly `0` in the output.
- Every entry where `mask == 1` must be scaled by `1 / (1 - p)`, not left unscaled.
- `dropout_backward` must apply the identical mask and identical scaling as `dropout_forward` did (dropout has no learnable parameters, but it still needs a backward pass so gradients continue flowing correctly to whatever comes before it in the network).
- Assume `0 <= p < 1`.

### Hints

<details>
<summary>Hint 1</summary>

`x * mask` alone zeroes the dropped entries but leaves the survivors at their original scale, that's "vanilla" (non-inverted) dropout, which requires special-casing at test time. Divide by `(1 - p)` as well to get the inverted version.

</details>

<details>
<summary>Hint 2</summary>

The backward pass mirrors the forward pass exactly: wherever an entry was zeroed on the forward pass, no gradient should flow back through it either; wherever it survived, its gradient gets the same `1 / (1 - p)` rescaling. `dropout_backward` is, syntactically, an identical expression to `dropout_forward`, just applied to `grad_output` instead of `x`.

</details>

## Theory

### The simple version

A sports team practices intentionally, on different days, without different star players present, so that every other player learns to carry the offense on their own, instead of everyone quietly relying on the same one or two stars every single game. Come the actual game (test time), the full roster plays together, and the team performs better as a WHOLE because no single player's absence would be catastrophic.

### The formula

```
forward:  y = (x * mask) / (1 - p)
backward: grad_x = (grad_output * mask) / (1 - p)
```

Where `mask` is a random 0/1 array, `P(mask_i = 1) = 1 - p` for each entry independently. The reason the forward and backward formulas are IDENTICAL in shape: dropout, viewed as a function, is exactly the same as `y_i = x_i * c_i` where `c_i` is a fixed constant (`mask_i / (1-p)`) per entry, and the derivative of a per-entry constant multiplication with respect to `x_i` is just that same constant, so the same constant multiplies the upstream gradient on the way back.

### How PyTorch actually implements this

`torch.nn.Dropout` generates its random mask from a Bernoulli distribution with keep-probability `1 - p` on every forward call during training (a fresh mask every call, not reused across steps), and applies exactly this `(x * mask) / (1-p)` inverted scaling internally. `nn.Dropout` automatically checks `self.training` (set by `model.train()` / `model.eval()`, which `[03-training-loop]`'s train/eval mode switching question implements the logic behind) and skips both the masking and the rescaling entirely in eval mode, simply passing `x` through unchanged, exactly the behavior the inverted scaling was designed to make possible. Because CPU-generating a fresh random mask on every forward call is itself nontrivial work, PyTorch's CUDA dropout kernel actually fuses the random-mask generation, the multiply, and the rescale into one GPU kernel launch rather than three separate ones.

## Explanation

`dropout_forward` computes `x * mask / (1 - p)`: multiplying by `mask` zeroes every dropped entry, and dividing by `(1 - p)` rescales the survivors so their expected total matches what the FULL, unmasked activation would have summed to.

`dropout_backward` applies the identical formula to `grad_output` instead of `x`: since dropout's forward pass is a per-entry multiplication by a fixed constant (`mask / (1-p)`), the backward pass multiplies the upstream gradient by that same constant.
